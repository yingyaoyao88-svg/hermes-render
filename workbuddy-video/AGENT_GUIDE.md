# 口播稿 → 知识讲解视频：Agent 制作手册

> 本手册写给要复用这套模板的 AI Agent。读完后，你应该能拿到一份新的口播稿，独立做出同样风格的视频：
> 界面演示（聚光灯、镜头推拉、鼠标点击、逐字打字）+ 知识卡片 + 离线中文配音 + 烧录字幕，输出 1080p MP4。
>
> 参考成品：`output/workbuddy-ep01.mp4`（WorkBuddy 新手教程第 1 期，3 分 53 秒）。

---

## 0. 一句话理解这套模板

**把视频当成网页来做。** 每一帧 = 一个网页在第 t 秒的样子。

- `scenes.json` 规定"说到哪句话时，画面是什么状态"（聚光哪个按钮、菜单开没开、输入框打了几个字……）；
- `tts.py` 逐句合成配音，量出每句话的起止时间，得到**时间轴**；
- `page/app.js` 的 `renderAt(t)` 根据时间轴把网页摆成第 t 秒的状态；
- `render.mjs` 用无头浏览器每 1/30 秒截一张图，交给 ffmpeg 与配音合成 MP4。

**配音决定时间，脚本决定画面，网页负责画，浏览器负责拍。** 这就是全部原理。

## 1. 为什么这样设计（核心设计决策）

| 决策 | 原因 |
| --- | --- |
| **配音先行，画面跟随配音时长** | 画面切换点 = 每句话开始的时刻。先有真实的语音时长，画面就天然对得上嘴型节奏，不需要手工对轴。 |
| **状态驱动，而不是写动画** | 每句话只声明"目标状态"（例如 `focus: "#wsBtn"`），引擎自动计算从上一个状态到新状态的过渡。写脚本的人不用关心动画细节。 |
| **所有动画由时间 t 计算，禁用 CSS transition** | 逐帧截图时真实时钟不可靠。动画进度都用 `(t - 开始时间) / 时长` 算出，同一个 t 永远画出同一张图，可以只渲染某几秒、某几帧来检查。 |
| **界面用 HTML 还原，而不是真实截图** | 构建环境通常访问不到目标软件。HTML 还原的界面每个按钮都有 id，可以被聚光、点击、放大；换成真实截图就失去了这种可编程性。 |
| **离线 TTS** | 云端 TTS（如 edge-tts）在受限网络下常被拦截。sherpa-onnx 的模型托管在 GitHub Releases，受限环境一般也能下载。 |

```

├── page/
│   ├── index.html        ← ★ 界面还原 + 覆盖层 + 知识卡片的 DOM（换产品主要改这里）
│   ├── style.css         ← 样式（1920×1080 舞台、窗口、深浅色主题变量、卡片样式）
```

## 5. `scenes.json` 完整规范

### 5.1 结构

```jsonc
{
  "meta": { "title": "...", "subtitle": "...", "episode": "第 1 期" },
  "scenes": [
    {
      "id": "three",                    // 场景唯一 id
      "chapter": "二 · 右边必看三个地方", // 左上角章节标签；空字符串则不显示
      "base": { },                      // 场景开始时的初始状态（每个场景从空状态 + base 开始）
      "lines": [
        {
          "text": "第一，中间的输入框。",   // 字幕原文（也是默认朗读文本）
          "say":  "……",                   // 可选：朗读文本与字幕不同时使用（数字、符号、引号）
          "state": { "focus": "#inputBox", "label": "① 输入框", "zoom": ["#inputArea", 1.35] }
        }
      ]
    }
  ]
}
```

### 5.2 状态的累积规则（重要）

1. 每个场景开始时，状态 = `base`。**上一个场景的状态不会带进来**，需要延续的就写进 `base`。
2. 场景内的每句 `state` 是**增量合并**：只写要变化的键，没写的键保持上一句的值。
3. 某个键设为 `null` = 删除它（例如关闭菜单 `"menu": null`、取消聚光 `"focus": null`）。
4. 值真正发生变化的时刻，会被引擎记为该键的"变化时间"，过渡动画从这个时刻开始。值没变就不会重播动画。

### 5.3 状态键参考

**通用画面键（换任何产品都能用）：**

| 键 | 取值 | 效果 |
| --- | --- | --- |
| `card` | 卡片名 / `null` | 全屏知识卡片，显示 `#c-<名>`；从界面切入或切出时淡入淡出 0.45 秒 |
| `cardStep` | 数字 | 卡片内 `data-step="n"` 的元素在 `cardStep ≥ n` 时出现，n 等于当前步时淡入上浮 |
| `focus` | CSS 选择器 / `null` | 黄色聚光框：框住目标、压暗其余画面；目标切换时框平滑移动 0.6 秒；自动限制在窗口内 |
| `label` | 文字 | 聚光框旁的黄色标注；优先放右侧，其次左侧，再其次上下；大区域（>450×450）放在框内左下角 |
| `big` | 文字 | 标注里的超大数字（如 `"90%"`） |
| `zoom` | `[选择器, 倍数]` / `null` | 镜头推近：放大并尽量让目标居中，不露出窗口外的空白；过渡 0.8 秒 |
| `cursor` | 选择器 / `null` | 鼠标指针移到目标中心，用时 0.7 秒；首次出现时从右下方滑入 |
| `click` | `true` | 鼠标到位后显示一次点击波纹 |
| `menu` | 菜单名 / `null` | 展开下拉菜单。若与 `cursor` 在同一句设置，会等鼠标到位（约 0.75 秒）后再展开 |
| `type` | 见下 | 输入框逐字打字 |
| `markers` | `true` | 在三个关键控件上依次弹出 ①②③ 序号 |
| `confused` | `true` | 在多个按钮上方弹出红色"？"（表现"不知道点哪"） |
| `wander` | `true` | 鼠标在界面上漫无目的地游走 |
| `theme` | `"dark"` / 省略 | 切换深色主题（CSS 变量实现） |
| `toast` | `"error"` | 顶部弹出红色错误提示 |
| `diagram` / `diagStep` | `"sandbox"` / 1-3 | 全屏原理示意图，分步出现 |

**`type` 的两种写法：**

```jsonc
{ "type": { "plain": "帮我把这周的会议记录整理成一份纪要" } }   // 在该句 75% 的时长内打完
{ "type": { "rich": "example", "upto": 2 } }                 // 分段打字：打到第 2 段，已完成的段按标签上色
{ "type": { "rich": "example", "upto": 3, "done": true } }   // 直接显示完整文本（用于下一场景的 base）
```

分段内容写在 `app.js` 的 `SEGS` 数组里，每段有 `t`（文本）、`tag`（标签，决定颜色）、`u`（第几句打出）。跨多句逐步打字时，每句把 `upto` 加 1。

**本期专用键（绑定 WorkBuddy 界面，换产品时按需改写）：**

| 键 | 效果 |
| --- | --- |
| `modeCycle` | 三个模式标签每 1.3 秒轮换高亮 |
| `tags` | 输入框下方依次亮起四要素标签 |
| `ws` / `wsPick` | 工作空间按钮文字 / 菜单里出现新建的文件夹 |
| `attach` | 输入框里出现附件 |
| `view` | `"chat"` 切到执行视图（与首页交叉淡化） |
| `chat` | 执行进度：0 已发送；1 步骤在本句内依次完成；2 全部完成；3 第二轮修改完成 |
| `preview` / `files` | 右侧预览面板滑出 / 显示文件树 |
| `reviseType` | 对话框里打出修改意见 |
| `rev` | `2` = 表格按新标准重算，并闪烁提示 |
| `warn` | 预览顶部显示"会覆盖原文件"警告 |
| `phone` | 标注里附加"手机 ➜ 电脑"图示 |

## 6. 渲染引擎 `app.js` 原理详解

### 6.1 状态计算：`stateAt(t)`

```
locate(t)   → 找到 t 所在的场景 si，以及已经开始的最后一句 li
stateAt(t)  → S = base；依次合并第 0..li 句的 state
              同时记录 since[键] = 该键最后一次变化的时间
                         lineOf[键] = 在第几句变化的
```

- `S`：此刻的完整画面状态；
- `since`：每个键的"变化时间"，所有过渡动画都以它为起点；
- `prevVal(st, 键)`：计算 `stateAt(since[键] - 0.001)`，即该键变化前的值，用于"从哪里过渡过来"。

### 6.2 过渡的通用写法

```js
const k = ease((t - st.since.focus) / 0.6);   // 0→1 的进度
rect = lerpRect(上一个目标的位置, 当前目标的位置, k);
```

聚光框、镜头、鼠标都遵循这个模式：**上一个值 → 当前值，按 `since` 起算的进度插值**。
若上一个值为空，改为原地淡入；当前值为空、上一个值不为空，则原地淡出。

### 6.3 每帧渲染顺序（顺序不能乱）

```
renderApp      设置界面内容（主题、打字、菜单、视图、表格…）——会影响布局
renderCamera   先取消镜头变换 → 测量目标元素 → 计算并应用新的镜头变换
renderDiagram  原理图覆盖层
renderSpot     在镜头变换之后测量元素位置 → 画聚光框和标注（位置才对得上）
renderMarkers  ①②③ 序号、"？"气泡
renderCursor   鼠标与点击波纹
renderCards    全屏知识卡片（最上层）
renderChrome   章节标签、字幕、进度条
```

### 6.4 必须遵守的实现约束

1. **禁止依赖真实时间**：`style.css` 里有 `* { transition: none !important; animation: none !important; }`。任何动效都要写成 t 的函数。
2. **需要被聚光、放大的元素不能 `display: none`**：隐藏的元素测不出位置，过渡会从 (0,0) 飞过来。菜单这类元素一律用 `opacity: 0` 隐藏。
3. **镜头测量要先复位**：`renderCamera` 里先 `transform = "none"` 再测量，否则会把已放大的尺寸再放大一次。
4. **舞台坐标固定**：视口固定 1920×1080、`deviceScaleFactor: 1`，`getBoundingClientRect()` 直接就是视频像素坐标。
5. **字体要预加载**：`render.mjs` 在开拍前 `document.fonts.load(..., document.body.innerText)`，否则前几帧会闪出后备字体。

## 7. 配音 `tts.py` 详解

- 模型：`vits-melo-tts-zh_en`（中英混读，单一女声，`sid=0`），语速 `SPEED = 1.08`。
- 节奏参数：片头静音 0.6 秒、句间停顿 0.28 秒、场景间停顿 0.7 秒、片尾留白 1.5 秒。
- 每句合成后记下 `start` / `end` 写回时间轴；场景的 `start` / `end` 包含停顿。
- 整轨音量归一化到峰值 0.9。
- **朗读文本规范化** `normalize()`（新视频按需补充）：

| 原文 | 问题 | 处理 |
| --- | --- | --- |
| `——` `%` | 词典里没有，会被静默跳过（日志 `Ignore OOV`） | 改为 `，`；`90%` → `百分之九十` |
| `“ ”` | 会读出奇怪的停顿 | 删除 |
| `WorkBuddy` `AI` | 连写的英文读音不准 | 改为 `Work Buddy`、`A I` |
| `【目标】` 这类标注 | 不该读出来 | 正则删除 |
| `60 分` 这类数字 | 一般能读对；读不对时 | 在该句 `say` 里写成 `六十分` |

**判断标准：** 运行 `tts.py` 时留意 `Ignore OOV '字符'` 日志，出现就说明有字符被吞掉，需要在 `normalize()` 或 `say` 里处理。

## 8. 做一期新视频的标准流程

### 第 1 步：拆稿

- 按"一口气能说完"拆句，每句 8–35 字（字幕一行放得下）。
- 按主题分场景，每个场景配一个 `chapter` 标签。
- 口播里的强调标记（【目标】等）从字幕和朗读中去掉，改用画面表达（颜色、标签）。

### 第 2 步：给每句配画面（最关键）

逐句问自己："**观众听到这句话时，眼睛应该看哪里？**"

| 口播类型 | 推荐画面手法 |
| --- | --- |
| 系列口号、开场、总结、预告、引导评论 | `card` 全屏卡片，`cardStep` 逐条出现 |
| "第一/第二/第三……" 介绍界面元素 | `focus` + `label` + `zoom`，必要时 `cursor` + `click` |
| "它会……"（描述行为） | 真的演示出来：`type` 打字、`menu` 展开、`view` 切换 |
| 讲原理（"为什么这么设计"） | `diagram` 示意图，分步出现 |
| 讲错误、坑 | `toast` 报错 / `warn` 警告，红色或黄色 |
| 列举多个并列项 | 每项一句，每句 `focus` 跳到对应元素 |
| 快速带过（"先混个脸熟"） | 不放大，只移动聚光框 |

**节奏原则：**
- 一句话只做一个主要动作，观众来不及看两个。
- 切到全屏卡片前，先把 `focus`、`cursor`、`menu` 置 `null`，避免卡片淡出后残留。
- 连续介绍小元素（侧边栏）时，在场景 `base` 里设一个固定 `zoom`，避免镜头来回跳。

### 第 3 步：还原界面（换产品时）

1. 在 `page/index.html` 里用 HTML 搭出目标软件的界面，**每个会被讲到的元素都给唯一 id**。
2. 菜单、弹窗默认 `opacity: 0`，放在对应按钮附近；需要跟随按钮位置的，在 `renderApp` 里用 `offsetTop` 动态定位（参考 `#wsMenu`）。
3. 颜色写成 CSS 变量，深色主题只需覆盖变量。
4. 画面右上角保留"界面为示意还原，以实际版本为准"的说明。

### 第 4 步：配音

```bash
python3 tts.py
```

检查输出里每句的开始时间和总时长，留意 `Ignore OOV` 日志。

### 第 5 步：抽帧检查（必须做）

每句大约在其时长的 30% 处取一个时间点，批量导出后拼图查看：

```bash
python3 -c "import json;d=json.load(open('build/timeline.json'));print(','.join(f\"{l['start']+0.3*(l['end']-l['start']):.1f}\" for s in d['scenes'] for l in s['lines']))"
node render.mjs --stills <上面输出的时间点>
python3 tools/contact_sheet.py <同样的时间点，用空格分隔>
```

按第 9 节的检查清单逐张看。只改画面时用 `tools/sync_states.py` 同步，再重新抽帧，**不必重新配音**。

### 第 6 步：整片渲染与交付

```bash
node render.mjs          # 后台运行
```

完成后用 ffmpeg 检查时长与音视频轨，并抽 1–2 帧确认，然后复制到 `output/`，连同 `subtitles.srt` 一起交付。

## 9. 质量检查清单

- [ ] 聚光框框住的元素和这句台词说的是同一个东西
- [ ] 标注文字没有遮住要看的内容（尤其是表格表头、菜单选项）
- [ ] 下拉菜单完整显示在画面内，没有被窗口边缘裁掉
- [ ] 放大后，要讲的元素在画面内且足够大（小字至少放大到 1.3 倍）
- [ ] 字幕一行放得下，没有与画面重要内容重叠
- [ ] 卡片切换时没有残留的聚光框、鼠标或菜单
- [ ] 鼠标的点击波纹出现在按钮上，菜单在点击之后才展开
- [ ] 打字在这句话说完之前打完
- [ ] 深色主题切回浅色时，所有元素颜色正常
- [ ] 虚构的数据（模型名称、倍率、学生成绩）有"以实际为准"的说明，或本身明显是示例
- [ ] `render.mjs` 输出没有"页面错误"
- [ ] 成片时长 ≈ `timeline.json` 里的 `duration`，有音轨

## 10. 踩过的坑

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| 配音里有字被跳过 | TTS 词典没有 `——` `%` 等字符 | 在 `normalize()` 或 `say` 里替换 |
| edge-tts 报 SSL 证书错误 | 受限网络拦截了微软 TTS | 改用离线 sherpa-onnx |
| 聚光框从左上角飞过来 | 上一个目标是 `display:none`，测出位置 (0,0) | 改用 `opacity: 0` 隐藏 |
| 下拉菜单盖住触发它的按钮 | 菜单写死了 `top`，而输入框高度随内容变化 | 在 `renderApp` 里按按钮 `offsetTop` 动态定位 |
| 菜单底部被裁掉 | 镜头对准的是输入区，菜单在其下方超出画面 | 该句的 `zoom` 改为对准菜单本身 |
| 大区域的标注盖住表头 | 标注放在框内左上角 | 大区域改放左下角 |
| 聚光框超出窗口边缘 | 目标元素贴着窗口边 | 把聚光框限制在窗口矩形内 |
| 放大后镜头露出黑边 | 只按居中算位移 | 位移限制在 `[W - W·s, 0]` 区间 |
| 前几帧字体不对 | 字体异步加载 | 开拍前预加载全部用到的字形 |
| `rm -rf build/stills/*` 被安全检查拦截 | `cd` 之后再用相对路径加通配符删除 | 不必删除：截图同名会被覆盖；非删不可时用绝对路径 |
| `git push` 返回 403 | 仓库没有给 Claude 写权限 | 让用户重新连接 GitHub 并安装 Claude GitHub App，**不要反复重试** |
